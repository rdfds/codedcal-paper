# Bounded color-group search — development specification

Frozen before new search outcomes, after the complete pooled initializer failed
field one's color case. The oracle-start diagnosis establishes a much better
single-code objective basin there; it does not establish an overlap mechanism.
This repair changes search, rather than replacing the objective.

Compare two round initializations: no correction and the existing ten-step
round-sum alignment, with bounded initialization and integer rounding. Search
all three possible 2+2 color partitions in both families; do not
choose the known injected assignment. Each partition receives opposite shifts
+k/-k, k[y,x] in {-8,-6,...,8}². Compute the author's normalized single-code
explained energy over the full 128-pixel input with twenty-pixel padding, preserving
all photons in the search domain. Precompute each group's code projections to
avoid redoing the same matrix multiplication for every geometry. Compose maps
on padded images rather than cropping between stages; both families share
the original input-energy denominator. Refine each
partition's best coarse grid point at its nine integer neighbors; ties prefer smaller
corrections, then partition order. Check the selected loss against actual author
TensorFlow code. No references, injected maps, gene calls or perturbation labels
enter calibration. The grid contains the previously exposed injected amplitude;
this is development, not fresh validation or an amplitude-general result.

Keep two separate policies: global group correction and the unchanged 50-step
author optimizer initialized by it. Every zero/common/color case on both exposed
fields and both frozen kernels is retained (24 records). Preserve the prior
24-record pooling failure and every original arm. Use unchanged windows, cuts,
three radii, support, yield, blanks and composition. Decode reuse requires exact
full-window input equality. No outcome-dependent policy switch.

Before public search, use balanced known-barcode synthetic images for 7/10 rounds:
zero and round-only controls plus each of the three color partitions at shifts
(3,1), (4,2), (5,3). Exact integer-image recovery is the stated control criterion.
Retain all 22 controls including failures. These controls test search/sign and
grid refinement; they do not supply biological validation. Arbitrary independent
four-color maps, nonrigid errors, shifts outside the search and asymmetric group
sizes are not represented. A deployment wrapper would have to handle/abstain on
those cases rather than claim universal coverage.

Public development goal remains >=0.95 native identity F1 and composition TV
<=0.05 in every nonzero global-search arm, >=0.95 F1 in zero cases. Refinement is
separate. Do not change cuts or upgrade independent validation/manuscript claims
because an exposed repair improves. Both fields are still one preparation.

Correction before public scoring: the first global implementation retained
destructive round-first alignment, failing six of 22 synthetic controls. All
records, source and log remain in global-repair-control-v1/, global_repair_v1.py
and global-controls.log. The revised implementation searches both no-round and
round-fitted families against the same original pixels and denominator, retaining
photons while composing maps. Each of six family/partition pairs gets 81 coarse
and nine refinement evaluations (540 entries, including repeated central points).
Twenty-pixel padding contains every candidate (round maps bounded to ten pixels,
group maps to nine). This changes search/support, not the single-code objective.
