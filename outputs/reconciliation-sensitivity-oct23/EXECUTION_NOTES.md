# Execution scope and fixed ingredients

The original coarse groups, at-least-20-localization group screen, event
formation and at-least-eight-valid-event group screen remain fixed, as do raw
precision filters and guard gaps. Newly lenient eligibility does not invent
events outside the original retained pre-source-QC candidate groups. Coverage
remains relative to original code-input localizations in valid panels.

The grid changes strict clustering radius and source eligibility only. Cluster
numbers have no physical meaning; sparse and dense partitions are compared as
equivalence relations. Baseline source rows are sorted within their original
round/group before comparison so a numbering change is not mistaken for a
scientific disagreement.

The protocol was committed in 59cacea before sensitivity outcomes. Scientific
implementation was committed in 5baf5dc. Historical Source Data 69 is read-only.
The dependency manifest records 143 original evidence and implementation files;
all raw inputs are also checked against the original per-member identities.
The sequential runner skips completed result files and refuses existing logs
for incomplete arms: no automatic scientific rerun or overwrite is permitted.

No new simulation response laws or updated-QC response fits are created. The
six existing CD20 response models retain every original qualification failure;
their coefficient uncertainty is newly propagated only for original QC. The
nine-view observed-data sensitivity is distinct from that six-preparation
conditional response calculation.

An early verification assertion incorrectly expected identical percentile
endpoints under the original bootstrap seed (26100761) and the new, committed
sensitivity seed (26102361). Source/group moments and point differences replay;
finite bootstrap endpoint variation is expected. The verifier now independently
replays the old seed to check old intervals, while preserving the specified new
seed for every sensitivity setting. No scientific result, seed, gate or setting
was changed in response to this check.

Before the dense SDC views, a performance defect was identified: indexing an
NpzFile member in the group loop decompresses the entire empirical events
array each time. Subsequent processes cache that exact ndarray once. The
initial implementation is retained byte-for-byte in sensitivity-initial.py;
dependency-revisions.json records both hashes. A regression test permits only
the caching edit and an added implementation-hash metadata field, and checks
exact equality of cached/reloaded slices. No grid, source operation, statistic,
uncertainty calculation or completed result is changed or rerun. The runner's
initial source hash remains its initial state; later results record their own
implementation hash.

The final report distinguishes a numerical bounded-fit return value from a
supported fit comparison. An empty source set, nonpositive pooled ratio at
either frequency, or optimizer boundary is unavailable for the narrowing
count; the original numerical result is still retained. Unbounded Fieller
sets are separately reported and do not become finite intervals merely
because a point fit exists. A regression control prevents unsupported fits
from being counted as reconciliation successes.
